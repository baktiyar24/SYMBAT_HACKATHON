# PharmaBoost AI

Работающий frontend интеллектуального рекламного модуля для SIMB-AD. Symbat Hackathon, 2026. Интерфейс на русском, суммы в тенге. Backend, база данных и реальная оплата не создавались.

## Структура

```text
pharmaboost-ai/
├── index.html       # оболочка, меню, верхняя панель, модальное окно
├── style.css        # тема, адаптивность, CSS-иллюстрации
├── script.js        # семь разделов, графики, калькулятор, демонстрация
├── api.js           # Fetch, маршруты, валидация, переключение режима
├── mock-data.js     # единый локальный симулятор данных и событий
├── config.js        # URL API и режим по умолчанию
├── API_CONTRACT.md  # модели, JSON и предварительные endpoint
└── README.md
```

HTML5, CSS3, Vanilla JavaScript ES-модули. Chart.js 4.4.8, Lucide 0.468.0 и Inter через CDN. Сборка и npm install не требуются. Упаковки нарисованы CSS.

## Запуск

Используйте любой статический HTTP-сервер, например стандартную команду при установленном Python:

```powershell
cd "путь\к\pharmaboost-ai"
python -m http.server 8080 --bind 127.0.0.1
```

Откройте http://127.0.0.1:8080. Альтернатива — Live Server в редакторе или статический хостинг. Это сервер файлов, не backend приложения. Не используйте file://: браузер ограничивает ES-модули из файловой системы.

Для CDN нужен интернет. При недоступном Chart.js отображается простая резервная диаграмма с подсказками; без Inter используется системный шрифт, без Lucide остаются текстовые подписи. Для офлайн-показа необходимо отдельно разместить CDN-ресурсы локально.

## Разделы

- **Обзор:** восемь KPI, двухосевой график, рейтинг кампаний, RPI и рекомендации.
- **Умная реклама:** объяснение алгоритма, формула, сигналы оптимизации.
- **Реклама по запросам:** поиск по словам, категориям и синонимам; рекламная подборка, каталог, объяснение объявления и тестовые покупки.
- **Реклама по скидкам:** процент 0–90%, активность акции, наличие, фильтры, сортировка, сравнение ранжирования и предпросмотр.
- **Эффективность:** два синтетических сценария, динамика событий, расходы, стандартные коэффициенты и CSV.
- **Аналитика:** калькулятор RPI с валидацией, факторы и рекомендации.
- **Настройки:** DEMO/API, URL, проверка соединения, сброс и документы.

Есть мобильное меню, модальные окна, toast, загрузка, ошибки и пустые результаты. Навигация без перезагрузки. Кампания фильтрует рекламу и аналитику; обычный каталог остаётся общим. Фильтры категории/наличия на странице скидок управляют таблицей; сравнение выдачи относится к указанному поисковому контексту.

## Демонстрация для жюри: 2–3 минуты

Нажмите «Запустить демо». Это сбрасывает прежние локальные данные для воспроизводимости. Двигайтесь кнопкой «Следующий шаг»:

1. Открывается демонстрационная аптека.
2. Подставляется запрос «Шампунь»; вручную искать также можно.
3. Отображаются доступные рекламные шампуни, отсутствующий исключён.
4. Открывается таблица акций.
5. Активируется скидка 35% на Gentle Care, цена — 3 640 ₸, порядок меняется.
6. Открывается реклама; регистрируются один тестовый показ и связанный клик.
7. В модальном окне нажмите «Продолжить демо». Создаётся тестовая покупка. Можно сначала нажать кнопку покупки вручную: двойного учёта не будет.
8. Открывается эффективность с обновлённой покупкой и выручкой.
9. Показываются пересчитанные CTR, CVR и RPI.
10. Открывается аналитика факторов. Нажмите «Готово».

«Сбросить демо» возвращает исходные данные. Пошаговый сценарий и локальный сброс недоступны в API; переключитесь в DEMO в настройках. Обычные тестовые действия в API идут только через тестовые endpoint.

## Данные и учёт событий

Единый симулятор содержит 8 товаров, 2 аптеки, 7 кампаний и два сценария по 7 дней (08–14 ноября 2026). Данные детерминированные, показатели агрегируются из общих дневных строк. Сценарии синтетические, это не результаты реального A/B-теста.

Демовремя фиксировано: 14 ноября 2026, 12:00 UTC+5. Акция сыворотки с витамином C закончилась. Fresh Ritual отсутствует и исключён из рекламы независимо от скидки. Базовая выручка отражает исторические цены; текущая скидка её не меняет.

Рендер, поиск и навигация не записывают показы. «Подробнее» рекламы создаёт явно тестовый показ и клик. Для одной карточки в сеансе переиспользуется транзакция, чтобы повторное открытие/ошибка сети не завышали счётчики. Покупка блокируется на время запроса и после успеха. Симулятор дедуплицирует ID и связь заказа с кликом. Органические покупки не меняют рекламные показатели.

Состояние хранится в памяти вкладки. Перезагрузка и сброс начинают новую демонстрацию. Для независимой повторной покупки того же товара используйте сброс. В production дедупликация обязательна на backend независимо от браузера.

## Формулы

```text
CTR  = 100 × Clicks / Impressions
CPC  = Spend / Clicks
CVR  = 100 × ConfirmedPurchases / Clicks
CPA  = Spend / ConfirmedPurchases
ROAS = Revenue / Spend
RR   = RelevantImpressions / Impressions
AR   = AvailableImpressions / Impressions
RPI  = 100 × (CVR / 100) × RR × AR
```

Нулевой знаменатель: доли и RPI — 0; CPC, CPA, ROAS — null, отображается «—». Отменённые заказы исключены. Общие коэффициенты вычисляются из сумм, не усредняются.

50 покупок / 1 000 кликов, RR=90%, AR=95% → RPI=4,275. Относительно 3,100 изменение +37,9%, а не +38,1%: сравнение использует неокруглённое значение.

RPI экспериментальный, не доказывает дополнительные продажи. Произведение RR и AR не измеряет совместное пересечение событий. Причинные выводы требуют атрибуции, контрольной группы и статистической проверки.

```text
Smart Score = 0.50 × Relevance + 0.20 × Discount + 0.30 × Performance
Discount = действующая скидка / 100
Performance = min(CVR контрольного периода / 10%, 1)
```

Факторы от 0 до 1. До оценки исключаются отсутствующие, недопустимые, нерелевантные товары и неактивные кампании. Relevance использует название, категорию и явный словарь; это не универсальная языковая модель. Веса и ориентир CVR=10% — гипотезы прототипа. Разбор доступен у каждого объявления.

## Подключение backend

В config.js:

```javascript
export const CONFIG = {
  API_BASE_URL: 'http://localhost:8000/api',
  USE_MOCK_DATA: false,
  REQUEST_TIMEOUT_MS: 12000
};
```

Либо выключите DEMO и задайте URL в «Настройках» на время вкладки. «Сохранить и проверить» запрашивает кампании. При ошибке API остаётся выбранным; автоматической подмены mock нет. Настройки доступны и при недоступном сервере.

Все запросы выполняет api.js, UI не вызывает Fetch. Ожидается оболочка `{ "data": ... }`. Полные модели и endpoint — в API_CONTRACT.md. Дополнительно предложен PATCH /api/products/{product_id} для редактирования предложения. Другие пути и форматы адаптируются в api.js.

При другом порту backend должен разрешить CORS origin frontend (например http://127.0.0.1:8080), GET/POST/PATCH/OPTIONS и Content-Type/Accept. Секреты не хранятся в браузере. Реальные подтверждения покупок приходят серверу от аптеки, /orders/demo используется только для тестов. API-режим не превращает демособытия в реальные.

## Проверки поставки

Выполнены проверки синтаксиса JS и 38 автоматических утверждений отдельным проверочным скриптом в рабочем каталоге: агрегаты, поиск, пустая выдача, наличие, просроченные/будущие акции, ранжирование, неизменность истории, дедупликация, выручка, RPI=4,275, нулевые знаменатели, маршрутизация API, HTTP-ошибка, не-JSON, неполная модель, сброс.

В браузере пройден 10-шаговый сценарий с покупкой, открыты семь разделов, проверены графики, калькулятор и ошибка при покупках > кликов, мобильное меню и пустой поиск. На недоступном локальном API отображается ошибка без mock-подмены. Успешная интеграция с реальным backend не проверялась: сервер не предоставлен. Контрактный адаптер проверен с имитацией Fetch.

Проверены desktop и mobile, включая отсутствие горизонтального переполнения страницы мобильного поиска. Это не исчерпывающая матрица браузеров и устройств.

## Границы

Нет реальной авторизации, оплаты, серверного хранения и автоматического трекинга видимости. Это интерактивный frontend с изолированным симулятором, подготовленный к REST. Диагнозы и история заболеваний не используются. Каталог — косметика, уход и гигиена, без лечебных обещаний.
